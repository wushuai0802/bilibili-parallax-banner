# 验证范围与复验方法

## Node与图像检查

```sh
npm run check
```

该命令构建组件、按catalog构建全部主题、运行单元/离线/制作流程测试，再独立检查生成结果与手工交付模板。当前数量以命令输出为准。

覆盖的主要行为：

- 底层几何、源图实际解码、透明区域、对齐画布、合成海报、文件引用与重要区域。
- 鼠标归位、横向拖动、纵向放行、双指取消、缩放宿主、减少动态和媒体失败。
- 自动模式接管与恢复，离屏/隐藏/失焦暂停，前进后退缓存，用户选择跨输入与尺寸变化保留。
- 容器快速变化、慢请求、忽略取消的旧响应、主题更换、超时、路由卸载和同容器重建。
- 源工程初始化、透明裁边、两端映射、哈希文件、可重复构建、部署ZIP范围及失败时保留上一版。
- 完整离线HTML在content://与file://地址下执行，并解码其实际内嵌图片。
- 保真源图层逐像素合成、文字丢失与构图变更拒绝、注册遮罩尺寸、原图变更失效、缓存产物损坏恢复，以及精简网站包的内容边界。

芙莉莲工程含3个关键区域、21种宽度和5个位移位置，共315次构图检查；独立的默认源图工程含17种宽度和5个位移位置，共85次。两者使用同一协议、生成器、渲染器和校验函数。

4:1工程覆盖24种容器宽度和5个位移位置，共120次构图检查。UBits浏览器支架另覆盖390、768、1024、1280、1440、1920屏宽及个人中心开合，核对4:1、关键头部与真实控件、原链接、静态回退和跨767px切换；原生触摸检查确认轮播只切换一次且不误触链接。支架不代替实际站点上线验收。

## 浏览器CI

```sh
npx playwright install chromium webkit
npm run build
npm run test:browser
```

CI在Ubuntu安装所需系统依赖，并在以下环境运行实际网页：

| 环境 | 检查内容 |
| --- | --- |
| Chromium电脑 | 宽度变化、真实DOM中的图层与标题、主题替换、失败海报、减少动态、离线页面 |
| Chromium触屏仿真 | 同上，加原生触摸事件的接管与恢复 |
| WebKit触屏仿真 | 同一套布局、状态和资源加载检查 |

实际页面覆盖280、320、390、767、768、1280、3440px，读取图像显示矩形和DOMMatrix计算关键区域，核对真实HTML标题、横向溢出与重复图层。另确认初始只请求当前端图片，以及自动模式存在非零位移。

390和1280px的成功截图、失败截图及追踪文件作为 `browser-proof` 工件保留7天。只有Chromium触屏项目运行原生触摸派发专项，其余项目对此专项明确跳过，不冒充触屏手势覆盖。

## 渲染图与浏览器截图

theme:build生成的contact-sheet、proofs和可选GIF是**布局模型渲染图**，便于美工发现裁切和留白问题；它们没有代替浏览器截图。浏览器CI另保存真实页面截图。

模型校验只保护已登记的区域，不能识别人脸、判断抠图审美、补绘真实性、前景真实像素遮挡或实际许可。网页文字位置应与textZones约定一致；实际标题、导航和按钮还需在宿主网站检查。

## 设备与性能边界

WebKit触屏仿真不等同实体iPhone，Chromium触屏仿真不等同所有Android WebView。实体设备的GPU、字体和电源策略属于独立验收范围。

默认触屏自动写入最多30fps，精细指针最多60fps；隐藏、离屏、失焦和减少动态时停止自动循环。首屏预置高度与海报示例在embed.html中。网站的整体LCP、CLS及设备帧率需要结合真实网络和宿主页面测量，不以Node测试数量代替性能结果。
