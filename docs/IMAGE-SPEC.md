# Banner 图片交付规范

这是新主题交付给 AI、画师和网站开发者的统一规范。推荐从[通用模板](../templates/theme/README.md)开始制作。

同一套原画可以供电脑和手机使用；最终分别导出两套构图与配置。源素材的拆层只需做一次，手机端可以复用人物和背景，重新调整比例、位置及留白。

## 1. 标准交付目录

```text
my-theme/
  theme.json                 # 素材来源、两端清单、主体安全区和文字区域
  desktop/
    banner.json
    01-background.webp
    02-subject.webp
    03-foreground.webp
    poster.webp
  mobile/
    banner.json
    01-background.webp
    02-subject.webp
    03-foreground.webp
    poster.webp
```

模板使用可编辑的原创 SVG 占位图，文件名以 `.svg` 结尾。替换为 WebP/PNG 时同步修改相应 `banner.json` 的 `src` 和 `poster`。根目录 `theme.json` 用于制作验收；运行时组件加载的是对应端的 `banner.json`。

交付时另附可编辑源文件和参考来源。源文件可以是 PSD、KRA、分层 SVG 或原尺寸透明 PNG；网站部署只需要导出文件。

## 2. 尺寸与格式

| 项目 | 电脑推荐模板 | 手机推荐模板 |
| --- | --- | --- |
| 逻辑画布 | 1920×216 | 375×200 |
| 导出倍率 `pixelRatio` | 2 | 3 |
| 每个图层和合成海报 | 3840×432 | 1125×600 |
| 默认切换范围 | 视口宽度至少768px | 视口宽度至767px |
| 高度策略 | 190–280px | 按200/375比例，最高280px |

模板按全宽横幅设计，此时容器宽度与视口一致。嵌入侧栏或固定宽度区域时，应按实际横幅容器宽度选择两端清单、登记验收宽度和约定断点。

必须遵守的关系是：**实际图片尺寸 = 逻辑画布 × pixelRatio**。同一端的所有图层保留完整画布和透明留白，禁止把人物图单独裁成紧贴轮廓的小图片。另一端使用自己的画布和坐标。

推荐尺寸可以调整，但必须同步修改清单、主体区域、文字区域和验收宽度。组件未填写参数时的历史默认值是1920×180、2倍导出3840×360；根目录几何示例采用这个默认值。新主题模板采用上表，不能混用两套尺寸。

| 内容 | 要求 |
| --- | --- |
| 背景 | 不透明 WebP、AVIF、PNG、JPEG；覆盖整个画布 |
| 人物和前景 | 保留真实透明区域的 WebP、PNG、AVIF；不能用纯色代替透明 |
| SVG | 明确声明实际 `width`、`height` 及逻辑 `viewBox` |
| 合成海报 | 不透明，与本端画布一致；用于加载与失败兜底 |
| 色彩 | 导出为 sRGB，避免带入印刷 CMYK 工作空间 |
| 文件体积 | 建议单张不超过300KiB，每端总计不超过1.5MiB；超出时校验给出提示 |
| 文件名 | 推荐ASCII、小写、连字符；文件名与清单引用严格一致 |

标题、搜索框、按钮和网站 Logo 由网页绘制；装饰画面不烘焙这些界面文字，以便改内容、无障碍访问和适配语言。

## 3. 分层与构图

从后到前排列背景、主体、前景；`banner.json` 的数组顺序就是绘制顺序。

- 背景补全抠出人物后留下的空洞，并去掉背景中重复的人物，避免视差移动时出现“双影”。
- 需要对齐拼接的背景图层使用 `fit:'canvas'`，共同铺满并保留位移余量。
- 独立人物使用 `fit:'contain',position:[0.5,1]`，等比显示并底部对齐；独立构图的主体无需随背景一起放大。
- 手机优先保留关键人物头部和物体，重新安排位置；不能只截取电脑画面的中间部分。
- 文字放在约定的留白区域内。模板在电脑左侧、手机左上预留文字区；宿主网页改排版时同步修改约定。
- 主体关键区域在左右位移两端都应距横幅边缘、约定文字区至少4个CSS像素。可以提高 `minimumMargin`。
- 原始素材只有半身时，可以在横幅下边缘收口；不要把截断的身体悬在画面中间。

一张扁平图片可以显示为静态图或整体平移。人物与背景独立移动需要抠图、补背景及分层制作；当前工具不自动识别人脸或补画素材。

## 4. theme.json 的坐标约定

| 字段 | 含义 |
| --- | --- |
| version | 当前为1，这是制作合同版本，不是组件包版本 |
| name | 主题标识 |
| artwork | author、source、license，记录实际作者、参考来源与使用许可 |
| breakpoint | 两端容器宽度分界，默认767；全宽时与视口分界相同，由网站方选择清单 |
| minimumMargin | 主体距边缘、约定文字区的CSS像素距离，默认4 |
| variants.desktop / mobile | 两端的清单路径、验收宽度、主体区域及文字区域 |
| manifest | 相对theme.json的本地清单路径 |
| viewports | 需要验收的横幅容器宽度；手机不超过分界，电脑大于分界 |
| protectedRegions | 每个关键头部、Logo或物体分别登记，不要只登记其中一人 |
| textZones | 网页约定的文字预留矩形；没有叠加文字时明确填空数组 |

主体区域格式：

```json
{"id":"hero-head","layerId":"subject","rect":[226,88,72,75]}
```

`rect` 是 `[x,y,width,height]`，单位为本端**逻辑画布像素**，原点为完整图层左上角。上例针对375×200手机画布；在3倍图片中对应 `[678,264,216,225]`。`layerId` 必须对应清单中的真实图层。

文字区域格式：

```json
{"id":"site-title","rect":[0.048,0.05,0.6,0.32]}
```

文字区域使用**相对实际横幅容器的0–1比例**，上例表示左起4.8%、顶起5%、宽60%、高32%的区域。它是宿主约定，不会自动生成标题或修改网页CSS；动态字体、按钮和导航的实际尺寸仍以网页验收为准。

`theme.json` 不会自动切换组件。网站在分界改变时销毁旧实例，再加载电脑或手机清单；参考[接入指南](INTEGRATION.md)。

## 5. 制作与验收流程

1. 复制通用模板，准备原画或分层源文件；记录实际素材来源与许可。
2. 制作同一主题的两端构图，按各自完整画布导出背景、主体、前景和合成海报。
3. 更新两端清单、主题名称、所有关键主体区域和宿主文字区域。
4. 在仓库根目录执行下方命令，修复缺文件、尺寸、透明、越界和文字区冲突。
5. 查看静止、最左、最右的效果，核对抠图边缘、重复人物、空洞、前景遮脸和实际网页文字。
6. 部署整个主题目录，使用版本目录或缓存失效策略；保留上一版以便回退。

```sh
npm ci --ignore-scripts
npm run validate:theme -- /path/to/my-theme/theme.json
```

单端素材可以独立检查：

```sh
npm run validate -- /path/to/my-theme/desktop/banner.json
npm run validate -- /path/to/my-theme/mobile/banner.json
```

`npm run check` 会验证仓库通用模板与现有示例。新增自己的主题时，显式传入它的路径；需要持续验收时将该命令加入自己项目的CI。

同画布、文件名、构图和位移都保持一致时，可以只换图片和合成海报。主体位置、人数、比例、文字位置或图层数量改变时，必须同步更新相应配置及安全区。

## 6. 自动校验的范围

校验会实际解码图片，检查引用、画布尺寸、透明区域和海报；再对声明的宽度及 `-1,-0.55,0,0.55,1` 五个位移进度，计算关键区域是否越界或进入声明的文字区。计算考虑图层缩放、底部对齐、位移和旋转；旋转时采用保守的包围矩形。

校验依据制作方登记的矩形，不自动寻找实际人脸，也不证明所有连续宽度都安全。它不检查前景的真实像素是否遮脸、抠图审美、ICC色彩准确性、授权真伪或实际网页文字溢出。这些项目要用画面与网页核对。

当前配对合同面向静态分层图片，采用 `mode:'aligned'`；视频和B站原生分层适配使用单独的验收流程。

## 7. AI制作入口与现有示例

把参考图片、本规范和[AI制作任务模板](../templates/theme/AI-BRIEF.md)一起交给后续AI，即可明确要求它交付两端素材、配置和验收结果。

`scripts/build-examples.mjs` 是芙莉莲专用示例构建脚本，包含该画面的裁切坐标和水晶位置。新主题按通用模板制作，不能将这些坐标当成任意海报的自动适配规则。
