# 图片格式、命名和替换标准

新主题的正式入口是[Banner图片交付规范](IMAGE-SPEC.md)，配有[通用双端模板](../templates/theme/README.md)、[AI任务说明](../templates/theme/AI-BRIEF.md)和 `npm run validate:theme` 整套校验。下面保留组件默认值、旧示例与素材替换方法，便于已有接入方对照。
v1.3新增[源工程流程](WORKFLOW.md)：theme:init与theme:build自动完成两端导出、海报、哈希、预览、报告和打包，优先从源工程模板制作新主题。

## 组件默认值与旧几何示例

| 项目 | 标准 |
| --- | --- |
| 逻辑画布 | 1920 × 180 |
| 2 倍导出 | **3840 × 360**，sRGB |
| 同画布图层 | 所有图层尺寸完全一致，不自动裁切透明边缘 |
| 背景 | 不透明 WebP / AVIF / JPEG / PNG |
| 中景和前景 | 带真实透明区域的 WebP / PNG；SVG 也支持 |
| 静态海报 | 全部图层合成，建议 WebP；加载失败与首屏兜底 |
| 手机海报 | 可选，建议单独构图；配置 `mobilePoster` 后手机使用该静态图 |
| 下载预算 | 建议单层 ≤300 KiB、总计 ≤1.5 MiB；这是优化建议，不是拒收无损图片的硬限制 |

比例和尺寸可配置，3840×360是组件默认尺寸与旧几何示例尺寸，并非B站每个图层天然都必须是这个尺寸。
新主题的推荐模板是电脑3840×432、手机1125×600；采用模板时需使用其中的清单参数，不能与上表的组件默认值混用。
SVG 必须同时声明明确的 `width="3840" height="360"` 和对应 viewBox，不能只写 viewBox；否则浏览器的天然尺寸可能按 300px 计算。

## 标准目录

```text
banner/summer/
  banner.json
  01_bg.webp
  02_mid.webp
  03_fg.webp
  poster.webp
  mobile.webp       # 可选
```

**JSON 数组从后向前绘制**：第一个是背景，最后一个是前景。命名数字只用于人类管理，不参与算法；不要根据 B站素材的文件名反推绘制顺序。

```json
{
  "version": 1,
  "baseWidth": 1920,
  "baseHeight": 180,
  "pixelRatio": 2,
  "poster": "poster.webp",
  "layers": [
    {"id":"sky", "src":"01_bg.webp", "offset":[6,0]},
    {"id":"hills", "src":"02_mid.webp", "offset":[28,6], "requireAlpha":true},
    {"id":"reeds", "src":"03_fg.webp", "offset":[64,12], "requireAlpha":true}
  ]
}
```

## 以后只换图片的流程

1. 画师保留相同画布、图层含义、文件名与透明区域，替换三个图层和合成海报。
2. 不增加图层、不改位移参数时，`banner.json` 不必修改。
3. 运行 `node scripts/validate-assets.mjs banner/summer/banner.json`。它会解码像素检查损坏、尺寸、真实透明区域和相对路径。
4. 上传整个素材目录，使用版本化目录或缓存失效策略，避免同名图片被 CDN 缓存。
5. 在网站实际宽度下查看，确认手机裁切、主体与导航不重叠。

图层数量或构图改变时，开发者调整清单。单张图不能自动拆出前景与人物，也不会自动生成呼吸或人物动画。

## 出血与安全区

组件为 `fit:'canvas'` 的同画布图层计算共同缩放，保留位移余量；不要求人为固定“3%出血”。美术仍应在边缘画完整的背景，避免透明区域或内容缝隙被位移揭开。

导航常占顶部 64px，Logo 常在左下；这是宿主网站约定，不是组件的固定遮挡区。
手机的横幅比例与桌面不同，中心裁切会丢失两侧内容。静态展示可以提供 `mobilePoster`；动态展示应提供独立手机图层，并将人物层设为 `fit:'contain',position:[0.5,1]`。不要只把手机海报接上后继续放大桌面人物层。

### 芙莉莲示例的可复用构图合同

| 项目 | 桌面 | 手机 |
| --- | --- | --- |
| 逻辑画布 | 1920×216 | 375×200 |
| 导出尺寸 | 3840×432，2倍图 | 1125×600，3倍图 |
| 使用范围 | 容器视口至少768px | 至767px |
| 背景 | canvas 铺满 | canvas 铺满 |
| 人物 | contain，底部对齐 | contain，底部对齐，三人重新排布 |
| 标题 | 左下，避开右侧人物 | 左上留白，头部在其下方 |
| 高度 | 190–280px | 按200/375比例，最高280px |

`themes/frieren/project.json`记录三个人物源图关键区域，由通用生成器转换为两端坐标，并覆盖280–5120px的21种宽度和两端位移。更换素材时只更新源工程；至少核对头部距四边4px、文字不压头部、位移不露底。“头部完整”指已标注区域，不会补出原图不存在的全身。

## 分层数据模式的区别

`mode:'aligned'` 使用上面的共同画布合同，适合反复换图。
`fromBilibiliSplitLayer()` 保留每张资源天然尺寸、155px 基准和原始布局参数，适合已拥有相应分层数据的接入方；不要把这种数据强行导出成统一尺寸再使用原始缩放。

校验器面向本地静态图片；视频需要维护端另行检查编码、时长、静音、首帧和播放策略，脚本会明确报“未校验”，不会假装通过。
